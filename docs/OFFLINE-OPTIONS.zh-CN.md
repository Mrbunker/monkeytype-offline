# 官方 Monkeytype 纯前端版：方案比较

## 共同约束

- 基于官方 `monkeytypegame/monkeytype`，保留来源、基线提交和 GPL-3.0。
- 保留官方输入、光标、计时、评分、结果图表和主要交互。
- 保留 time / words / quote / zen / custom、语言、引文、主题、字体、声音和本地可用设置。
- 删除账号、认证、云同步、排行榜、社交、广告、遥测、远程文本生成及对应依赖。
- 实现本地历史、PB、筛选、趋势和 JSON 备份。
- 交付完整静态目录，通过本地 HTTP 或静态托管运行。词库等同源静态请求允许；运行时不依赖外部服务。
- 第一版不增加 PWA、桌面壳、单文件打包或多个构建版本。

## A：沿用官方结构，直接改成本地版

保留官方目录、页面组织、状态及 collection 的主要结构，逐处删除在线分支，把原持久化调用改为本地实现。

- 优点：页面变化少，容易逐文件对照官方，初期结构改动最少。
- 代价：本地数据访问容易散落在结果页、历史页、设置等位置；删除、导入、PB 重算需要额外防止规则重复。
- 适用：主要目标是个人使用、改动较少，愿意长期沿用官方内部结构。
- 要求：真正删除不需要的模块，不保留假登录或模拟 API；保留目录不代表保留云端数据语义。

## B：保留官方界面与引擎，集中本地数据规则（推荐）

保留官方前端架构、核心模块和资源，在 `frontend/src/ts/offline/` 集中本地数据、规则和备份。官方页面通过本地状态及 collection 读取数据。

依赖方向：页面/collection → 本地状态及操作 → 规则/存储。存储模块不依赖页面、弹窗或登录状态。

| 模块 | 责任 |
| --- | --- |
| `results.ts` / `types.ts` | 本地结果格式、有效性约束、PB 分组与重算 |
| `storage.ts` | IndexedDB 事务、读写删除、去重、容量限制 |
| `state.ts` / `stats.ts` | 页面状态、错误/重试、跨标签通知、派生统计 |
| `backup-schema.ts` / `backup.ts` | 版本化格式、完整校验、合并及偏好恢复 |
| `favorite-quotes.ts` | 本地引文收藏 |
| 官方 `config/` | 沿用设置应用机制，仅保留本地持久化 |
| 官方历史页 | 复用筛选、表格、图表，增加本地数据管理入口 |

- 优点：保留官方体验；本地数据规则集中，可单独验证；不需要重新实现打字引擎和历史图表。
- 代价：仍需理解和修改官方历史状态、collection 与页面间的耦合；不是完全独立的可插拔模块。
- 适用：完整可用的纯前端版本，并计划继续维护。
- 边界：只有本地后端，不设计多后端接口、云端兼容层或虚拟用户。

## C：抽取官方核心，组织为独立前端应用

保留官方输入、计时、评分、渲染及静态资源，重新组织应用入口、路由、设置和历史页面；将核心与 UI、存储依赖逐步分离。

- 优点：长期应用边界清楚，便于大幅改变产品界面与功能。
- 代价：官方核心与全局设置、DOM、控制器存在耦合，不能直接当独立库导入；需要大量拆分和体验回归，上游更新合并成本最高。
- 适用：明确要发展成独立产品，愿意承担持续重构成本。
- 要求：继续使用官方核心实现并保留归属；不得替换为另一套打字项目，也不能把近似体验当作等价验收。

## 推荐实施顺序：B

1. **固定来源与行为基线**：记录官方提交及工具链；明确保留模式、资源、评分规则与外网功能清单。
2. **完成纯静态启动链**：删除在线启动、路由、命令和依赖；无服务端凭据即可构建；统一静态资源路径。
3. **完成练习数据闭环**：真实输入 → 官方结果计算 → 本地事务保存 → 历史/PB → 刷新恢复。失败可见、可重试；删除会重算 PB。
4. **完成数据管理**：备份覆盖成绩、设置、自定义主题及收藏；损坏文件写入前拒绝；重复导入不新增重复记录。明确偏好恢复失败和上传文件未包含的语义。
5. **完成验证与交付**：各模式、语言/主题/声音、跨标签同步、禁用存储；根路径/子路径部署；运行时外部请求审计；格式、类型、测试、构建。最后落入 `~/codes/lz` 并推送可审查分支。

每一步均以可运行结果验收，不以删除文件数量或编译成功代替功能验收。
